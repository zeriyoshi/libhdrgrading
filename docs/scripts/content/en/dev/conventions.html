The full rules are in {{src:CLAUDE.md}} (Japanese). This page summarizes them; what can be checked mechanically, {{src:scripts/check_style.py}} checks in CI.

C code

  • C11; the fixed-width types of stdint.h and bool; the smallest type that fits; unsigned unless a sign is needed.
  • Declarations at the top of the function only, never in nested blocks or for headers. One declaration statement per type (pointers, arrays and initializers of the same type share it), in this order: const ones, project and dependency types, uint64_t … uint8_t, int64_t … int8_t, size_t, bool, char, double, float, void *.
  • Braces always. Every typedef ends in _t.
  • A file is ordered: includes, macros, static inline functions, static functions, ordinary functions, exported functions (written with extern).
  • Blank lines between the logical steps (after declarations, before a block unless the previous statement sets what it tests, after a closing brace, before a return that follows other statements, between allocation, assignment, side effects and cleanup).
  • Comments only where the code does not say it. The SPDX header (Apache-2.0 OR MIT) on every file.
  • Format with .clang-format, analyze with .clang-tidy (LLVM 23, the same as zendriver's common/).

Memory

  • Nothing under src/ calls malloc and the like directly: the library uses hdrg_mem_* (the context's allocator; aligned blocks with hdrg_mem_aligned_alloc), built-in filters and GPU layers the API table's mem_*. A dependency that allocates what it asks the caller to free is freed with free on a line saying "the dependency's" (check_style's raw-alloc).
  • Real-time paths hold no full-resolution float planes.

Determinism

  • Random values and dithers come only from the counter hash of {{src:src/foundation/include/hdrgrading/foundation/hash.h|hash.h}} (key, x, y, sample); rand() and sequential random streams are not allowed.
  • Transcendental functions come from {{src:src/foundation/include/hdrgrading/foundation/math.h|math.h}} (and, in pixel loops, {{src:src/foundation/include/hdrgrading/foundation/fmath.h|fmath.h}}), never libm's powf, expf, log2f.
  • Parallel work goes through the context's pool with a fixed split (hdrg_exec_t); the output never depends on the thread count. The FP environment is pinned at every entry point and worker; contraction is off (-ffp-contract=off).
  • The three temporal features are plugins the library calls through the stages' ABI alone, chosen like any built-in plugin (HDRG_WITH_TEMPORAL): the statistics across frames in the STATS plugin ({{src:src/plugins/stats}}), the motion-compensated interpolation in interp (HDRG_INTERP_MC), the multi-frame upscaling in edge (HDRG_SCALE_TEMPORAL). The core knows nothing of the build: a session's defaults follow the filters there are (a STATS filter: the past window). What touches them stays in those plugins, and a test of them goes by the generated HDRG_BUILTIN_STATS / _INTERP_MC / _SCALE_TEMPORAL: the build passes with them off (the default) and on (temporal).

The public API and the plugin ABI

  • A public function is declared on one line of a public header with HDRG_API: CMake builds the shared library's export list from those lines and test_exports checks it.
  • Status codes, kinds and flags are fixed uint32_t / uint8_t constants, not enums; structs that grow carry struct_size.
  • The filter ABI ({{src:include/hdrgrading/filter.h}}) stays at version 1 until it is frozen; until then, its table, signatures and meaning may change without a version bump, and the table is ordered by purpose.
  • Built-in plugins ({{src:src/plugins}}) include only the public headers, their own directory and the layers they build on ({{src:src/foundation}}, {{src:src/gpu}}, {{src:src/plugins/shared}}), never the core (check_style's filter-include); external plugins and the bindings, the public headers alone. Strings from plugins are taken with explicit lengths, validated and copied.
  • The built-in plugins that HDRG_PLUGINS_EXCLUDE can leave out (the list in {{src:src/plugins/CMakeLists.txt}}) stay so: the library runs without each (its defaults off, an explicit use {{api:HDRG_ERR_UNSUPPORTED}}), which minimal keeps true, and the tests avoid what is left out.

SIMD and shaders

  • A kernel is written once in {{src:src/kernels/vmath.h}} over the per-ISA primitives (v_<isa>.h); every tier follows the scalar reference's operations, without approximate instructions; a multiply followed by an add is hdrg_vf_fma, fused or not by HDRG_WITH_SIMD_FMA. A new kernel comes with its comparison in test_kernels.
  • WGSL is the source of every shader; regenerate MSL / SPIR-V / HLSL with {{src:scripts/gen_shaders.sh}} and commit them. A var in a loop always has an initializer (lavapipe does not reset one without it).
  • GPU results agree with the CPU within L2; add the comparison to the GPU tests.

Presets and evaluation

  • PHOTO's defaults are tuned by fidelity numbers (16-bit truth, PSNR against undegraded originals, chroma error, texture kept).
  • ANIME's defaults and the choice of methods are judged by eye at 200 to 400 %; numbers are regression checks, not rankings. Line art is left alone by default.
  • Evaluation images are kept out of the repository and the public pages.

Records

  • {{src:CLAUDE.md}}: the file structure, kept current when files or names change.
  • Generic behavior comes first; nothing is tuned for one platform or service.
