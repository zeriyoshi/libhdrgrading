Tests use Unity ({{src:third_party/unity}}) and run through CTest. Every configuration runs the whole suite: the guarantees cross modules, so tests are not picked by what changed.

Test suites

DirectoryWhat it checks
{{src:tests/unit}}Modules on their own: noise estimation, color, the plan and the lights, the render, Y'CbCr conversions, the session's contracts, the luminance rules' evaluation set, the SIMD kernels against scalar (checkasm style), math, hash, threads and the pool; the Metal and Vulkan lower layers.
{{src:tests/conformance}}The library from the outside: the output forms, gain maps, HAGC, gamut, determinism (thread counts, FTZ, SIMD tiers), allocation balance and failure sweeps, plugins and the stage runner, MCTF, interpolation, grain, upscaling, dynamic metadata, AVIF, HEIF, the GPU versions against the CPU (WebGPU, Metal, Vulkan), fuzz seeds.
{{src:tests/plugins}}Test plugin modules (a scaler, ABI versions too new and too old).
{{src:tests/ffmpeg}}, {{src:tests/gstreamer}}, {{src:tests/vapoursynth}}The bindings: every frame equals the session's output byte for byte; colors, metadata, timestamps, latency, output rates.
{{src:tests/wasm}}The browser module on node (bytes equal to the same build's hdrg-cli).
{{src:tests/install}}The shared library's exported symbols equal the HDRG_API list; an installed consumer builds through the CMake package and pkg-config.
{{src:tests/tools}}hdrg-video's HDR10+ and ST 2094-50 JSON.
{{src:tests/fuzz}}fuzz_convert (libFuzzer over hdrg_convert) and fuzz_seeds (the seed corpus, also used by test_seeds).

minimal runs the whole suite on a build without the optional built-in plugins; the tests of those left out are ignored (HDRG_TEST_REQUIRE_BUILTIN, HDRG_TEST_BUILTIN_STATUS in {{src:tests/test_util.h}}) or not built (hdrg_builtins_have in {{src:CMakeLists.txt}}). Before tests, look at the free memory: {{src:scripts/jobs.sh}} sets the parallelism, and warns and runs one job at a time when the free memory leaves room for less than one job. Valgrind runs nightly in CI only ({{src:.github/workflows/nightly.yml}}), at -O0.

CI

  • {{src:.github/workflows/ci.yml}}: style and format checks (with the shader check, the Actions lockfile and the docs), Linux (amd64 / arm64, GCC / Clang, Debug / Release, without lcms2, with the temporal features), sanitizers, fuzzing, the FFmpeg filter, WASM, coverage on 10 platforms merged into one report, macOS, Windows, the GUI.
  • {{src:.github/workflows/nightly.yml}}: Valgrind.
  • {{src:.github/workflows/pages.yml}}: GitHub Pages (these docs as the site, the demo, the merged coverage).

The Actions cache keeps what does not change from run to run, written only outside pull requests: the development image's layers, FFmpeg's clone of its tag and the ccache of its compiles (the filter job), Emscripten's cache per WASM build (and the demo's), and the fuzzing corpus, which grows from run to run (a crash's input is uploaded as an artifact).

Determinism levels

LevelScopePromise
L0 (public)The CPU path's pixels before encoding, gain maps, metadataByte-identical for the same input, settings, build and SIMD tier, whatever the thread count, run or FP environment
L0xAcross SIMD tiers, compilers, OSesWithin a tolerance of the scalar reference (measured: at most one code, a tiny share of samples)
L2GPU versions against the CPUWithin a tolerance; the golden is always the CPU scalar reference
Not promisedEncoded bytes (jpegli and libjxl pick their instructions; the system's libaom differs by version and, in some versions, by its thread count); vendor-specific filters (MetalFX)—
VideoSession outputsUnder L0, WINDOWED, TWO_PASS and STATIC are pure functions of the input sequence and settings: equal after a seek. RECURSIVE is not.

{{src:tests/conformance/test_determinism.c}} checks thread counts and FTZ, and that the exact SIMD tiers equal scalar; {{src:tests/unit/test_kernels.c}} compares every tier's kernels with the scalar ones.
