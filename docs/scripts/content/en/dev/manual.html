Everything under {{src:docs}} except {{src:docs/scripts}} and {{src:docs/assets}} is generated; the same build is the GitHub Pages site. The generator is one Python script with no dependencies beyond the standard library (Python 3.9 or later).

python3 -I docs/scripts/build.py            # rewrite docs/ (only the files that change)
python3 -I docs/scripts/build.py --check    # exit 1 when docs/ is out of date
python3 -I docs/scripts/build.py --strict   # also fail on diagram layout warnings
python3 -I docs/scripts/build.py --out DIR --site --source-base https://github.com/OWNER/REPO/blob/SHA
                                              # the site to publish: the docs (assets too) in DIR,
                                              # its top linking demo/ and coverage/, source links
                                              # to the repository on GitHub

Placeholders

The page bodies are HTML with placeholders that the build expands and checks, so a renamed file or symbol breaks the build instead of leaving a dead link:

PlaceholderBecomesChecked
{​{fig:NAME}}The diagram, inline (so the theme switch reaches it), with a link to its SVG fileThe diagram exists; unused diagrams are warned about
{​{src:PATH}}, {​{src:PATH|TEXT}}A link to a file or directory of the repositoryThe path exists
{​{api:SYMBOL}}, {​{api:STRUCT.MEMBER|TEXT}}A link into the API referenceThe symbol is in a public header
{​{page:NAME}}, {​{man:NAME}}, {​{dev:NAME}}A link to a page of the same part, of the manual, of dev/The page exists

Diagrams

A diagram is a Diagram(name, width, height, title, desc) with box (a kind picks the color: app, api, entry, core, io, plugin, filter, gpu, common, ext, data), group, edge (sides, anchor fractions sa / da, waypoints via, dashed, a label), line and text. The build writes docs/<lang>/img/<name>.svg for each language and inlines the same SVG into the pages. It estimates text widths and warns when a label does not fit its box or boxes overlap; the estimate is conservative, so look at the result in a browser too. The SVGs follow the system's light or dark theme, and the page's theme switch when inlined.

The API reference

The headers document themselves with plain comments before declarations and after members. Doxygen and libclang only take doc comments (/** */, ///<), so using them would mean rewriting every header comment or adding a dependency to the build; {{src:docs/scripts/apiref.py}} reads the headers' own layout (kept by clang-format and check_style.py) instead. It stops with an error on a line it does not understand, and the build fails unless every HDRG_API function of the headers is in the reference. The English pages show the comments as written; the Japanese pages show each in Japanese with the English under it, and identifiers in both link to their entries.

The translations are in {{src:docs/scripts/api_ja}}, one file a header, each comment keyed by a hash of its English, so a comment that does not change keeps its translation and only new or changed ones are translated ({{src:docs/scripts/api_ja/README.md}}: the steps, the rules and the terms). A plain build brings the files up to date with the headers (a new or changed comment comes in with "ja": null, an unused one goes) and fails while a comment is untranslated or a translation does not match its English (its blocks, list items and identifiers); python3 -I docs/scripts/apiref.py docs/scripts/api_ja/<header>.json checks one file.

Checking

Run --check after changing a public header or a page source to see whether the generated files must be rebuilt and committed. CI's repository checks run --check --strict ({{src:.github/workflows/ci.yml}}), so a header change without the rebuilt manual fails there.

Publishing

GitHub Pages ({{src:.github/workflows/pages.yml}}) builds the docs again as the whole site with --out site --site and --source-base set to the commit on GitHub, so its source links reach the files the pages describe (a directory under tree/, a file under blob/, the API reference's line anchors too); the site's top (the docs' own index.html) also links the WASM demo and the coverage the other jobs put beside it (when the CI run has no merged coverage, the site still goes out, with a page saying so in its place). {{src:scripts/wasm_demo.sh}} builds the same site with the demo into build/web to try locally, and the CMake target hdrg_web (cmake --build <build> --target hdrg_web) builds the site without the demo into <build>/web. The committed docs keep relative links for browsing a checkout.
