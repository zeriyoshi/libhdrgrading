The library's dependencies are built from the sources in third_party/ by CMake (nothing prebuilt); the AVIF and HEIF modules take the system's libavif / libheif. One command configures, builds and tests a preset.

First build

scripts/fetch_deps.sh                              # the submodules and jpegli's nested deps
scripts/jobs.sh cmake --workflow --preset dev      # configure + build + test, parallel within free memory

{{src:scripts/jobs.sh}} sets CMAKE_BUILD_PARALLEL_LEVEL and CTEST_PARALLEL_LEVEL to min(cores, (free memory − an eighth of the total, at least 2 GiB) / 1 GiB) and, when the free memory leaves room for less than one job, warns and runs one job at a time. Linux runs in the development image: {{src:scripts/docker_dev.sh}} runs a command in the same image as the DevContainer ({{src:.devcontainer}}: Debian 13, LLVM 23, GCC 16, Valgrind, emsdk, Dawn with lavapipe, VapourSynth, FFmpeg and GStreamer), with build directories build/linux-<preset>. The container's ~/.cache (Emscripten's system libraries and ports, ccache) is a Docker volume kept between runs; HDRG_DEV_CACHE mounts a host directory there instead.

Main options

The names follow one scheme: HDRG_WITH_<name> a dependency, a backend or a feature built in, HDRG_BUILD_<name> something made beside the library, HDRG_PLUGINS_EXCLUDE the built-in plugins left out.

Options off by default

HDRG_WITH_TEMPORAL (with HDRG_WITH_TEMPORAL_FILTER, _INTERP and _SR), HDRG_WITH_AVIF and HDRG_WITH_HEIF are off by default because we cannot say for certain that using them is safe with regard to third-party rights. Turning them on is at your own risk: build the library yourself. The presets temporal, avif and heif and the coverage presets turn them on for this project's own verification, and a configure with any of them on says so.

GPU toolchains

  • Dawn: {{src:scripts/build_dawn.sh}} builds the pinned tag into build/deps/dawn (the development image has it in /opt/dawn; the tag must match the Dockerfile's DAWN_TAG).
  • Tint: scripts/build_dawn.sh --tint builds Tint's CLI; {{src:scripts/gen_shaders.sh}} regenerates the MSL, SPIR-V and HLSL from the WGSL (--check fails on a difference). Commit the generated files with the WGSL.
  • Vulkan: only the headers at build time; Mesa's lavapipe runs the tests in the development image.
  • x86 on Apple silicon: -DCMAKE_OSX_ARCHITECTURES=x86_64 -DHDRG_WITH_WEBGPU=OFF runs under Rosetta 2 (SSE4.1; AVX2 with ROSETTA_ADVERTISE_AVX=1).

FFmpeg

The development image has Debian's FFmpeg 7.1. On macOS, {{src:scripts/build_ffmpeg.sh}} builds the latest stable into build/deps/ffmpeg; configure with PKG_CONFIG_PATH=$PWD/build/deps/ffmpeg/lib/pkgconfig. For the FFmpeg filter: install the shared library (cmake --install build/release --prefix build/deps/hdrgrading), then scripts/build_ffmpeg.sh --filter build/deps/hdrgrading builds a patched FFmpeg in build/deps/ffmpeg-filter, and a configure with its pkg-config path adds test_filter (with -DHDRG_WITH_TEMPORAL_INTERP=ON it also checks the filter's fps; the filter loads the test build's library).

WebAssembly

scripts/docker_dev.sh bash -c 'source "$HDRG_EMSDK_DIR/emsdk_env.sh" && cmake --workflow --preset wasm'
scripts/docker_dev.sh scripts/wasm_demo.sh            # the site in build/web: the docs, five modules and the demo

The pthreads builds create their pool's workers up front (PTHREAD_POOL_SIZE); WASM SIMD128 has no FMA, so it is always exact.

Installing and using

cmake -B build/out -DCMAKE_BUILD_TYPE=Release -DBUILD_SHARED_LIBS=ON
cmake --build build/out
cmake --install build/out --prefix /usr/local
find_package(hdrgrading 0.0.1 REQUIRED)
target_link_libraries(app PRIVATE hdrgrading::hdrgrading)

Or pkg-config --cflags --libs hdrgrading (--static for the static library, which also brings the C++ runtime and the dependencies). Both packages are relocatable. The version is 0.x (SOVERSION 0) until the API is frozen; a minor version may break compatibility. The static library contains the bundled dependencies' symbols; an app that links its own libpng or zlib statically should use the shared library or HDRG_WITH_SYSTEM_DEPS.
