The library is one static or shared library (libhdrgrading) built from layers with one direction of dependency: callers use the public headers, the entry points run the pipeline, and the pipeline uses the engines below it.

The layers

LayerWhereWhat it holds
Public API{{src:include/hdrgrading}}{{src:include/hdrgrading/hdrgrading.h|hdrgrading.h}} (the context, settings, still conversion, statistics), {{src:include/hdrgrading/video.h|video.h}} (sessions, the 3D LUT export), {{src:include/hdrgrading/gpu.h|gpu.h}} (the device the app shares, frames on the app's GPU, the shaders and state to run the apply pass there), {{src:include/hdrgrading/metadata.h|metadata.h}} (HDR10+ and ST 2094-50 and their T.35 payloads), {{src:include/hdrgrading/sidedata.h|sidedata.h}} (a frame's noise, motion and film-grain side data), {{src:include/hdrgrading/plugin.h|plugin.h}} (registering plugins, adding filters, choosing the writer), {{src:include/hdrgrading/filter.h|filter.h}} and {{src:include/hdrgrading/codec.h|codec.h}} (the ABI a plugin implements: filters, readers, writers). Every exported function carries HDRG_API; a shared build exports those alone.
Context and settings{{src:src/context.c}}, {{src:src/params.c}}, {{src:src/priv.h}}The allocator, the thread pool, the SIMD tier, the GPU mode, the plugin host with the built-in plugins registered, the last statistics. The presets' defaults, the checks of every setting and the settings by name (the hdrg-cli option names the bindings use).
Entry points{{src:src/convert.c}}, {{src:src/session}}, {{src:src/lut3d.c}}, {{src:src/core/dynamic.c}}Still conversion (decode, orientation, pipeline, container), video sessions (frame queue, scene cuts, flash limiter, output rate, latency report; the statistics across frames through the STATS stage), the STATIC mapping as a 3D LUT, the HDR10+ and ST 2094-50 payloads.
Pipeline{{src:src/pipeline}}, {{src:src/pipeline.h}}, {{src:src/host/defaults.c}}A sequence (the source color and its tables, the color LUT, the apply pass's scratch) and its frames: analysis, plan, render, the bind to the SCALE stage and the apply pass in bands. It also opens the PREFILTER chain and picks the built-in filters (their GPU versions under a GPU context).
Containers and I/O{{src:src/container.c}}, {{src:src/io}}, {{src:src/host/codec_host.c}}The codec host (the readers probed in turn, the conversion's writer with its options), what the host gives a writer: the gain map and its metadata (ISO 21496-1, XMP), ICC profiles and the HAGC tag, the measured light. The codecs themselves are plugins ({{src:src/plugins}}).
Core{{src:src/core}}Pass A (analyze, noise, the judged lights' records for the ANALYZE stage and their boosts scaled by its chances), pass B (plan), the render, pass C (apply), color (the color of a source, gamut mapping, the 3D LUT), Y'CbCr conversions, grain resynthesis, the motion side data, the row-parallel executor. The GPU versions of the core (gpu_core, gpu_convert, gpu_apply, gpu_analyze, gpu_gather) sit here too.
SIMD kernels{{src:src/kernels}}The hot loops of passes B and C, written once over per-ISA primitives (SSE4.1, AVX2, NEON, WASM SIMD128; AVX-512 and SVE provisional) and checked against the scalar reference.
Plugin host{{src:src/host}}Registration, validation, policy and freezing of plugins, the module loader, options, the stage runner (bands, whole frames, time windows, clips, ASYNC jobs in flight, device frames), the ANALYZE and STATS stages, the job frame formats, and the context's GPU devices, given to the plugins as native handles through the share ABI (gpu_share.h).
Built-in plugins{{src:src/plugins}}Each a CMake project of its own, linked into the library and registered at context creation through the public ABI: one per family of filters (scalers, deblocking, deringing, defringing, debanding, spatial and temporal noise reduction, frame interpolation, most with WebGPU, Metal and Vulkan classes and their shaders; MetalFX's scaler on Metal alone), the light predictor (ANALYZE), the temporal statistics (STATS, with the opt-in HDRG_WITH_TEMPORAL) and the codecs (JPEG, PNG, GIF, JPEG XL); AVIF and HEIF are loadable modules of the same kind. A build can leave the optional ones out (HDRG_PLUGINS_EXCLUDE). They include only the public headers and the layers below (checked by scripts/check_style.py).
GPU layers{{src:src/gpu}}A project of its own (hdrgrading-gpu): WebGPU over Dawn, Metal, Vulkan (loaded at run time), the common layer of Metal and Vulkan (gk.h), Apple's CVPixelBuffer, Android's AHardwareBuffer import, and the GPU plugins' part (the context's native device wrapped in the plugin's own layer objects, the jobs' frames). Not public API.
Foundation{{src:src/foundation}}A project of its own (hdrgrading-foundation) the library and its plugins build on: allocation macros, libm-free math (exact references and per-pixel float polynomials), the counter hash, the floating-point environment, threads, the persistent pool, a monotonic clock, and the share ABI of GPU devices and device frames between the library and its plugins (gpu_share.h).
WebAssembly layer{{src:src/wasm}}A function-only interface for JavaScript: settings by name, conversion, the interactive preview's state.

The shape of the build

  • The sources compile once into an object library; hdrgrading (static, or shared with BUILD_SHARED_LIBS) is those objects plus the built-in plugins', the foundation's and the GPU layers' and the bundled dependencies' (jpegli, Highway, libpng, zlib, giflib, lcms2, libjxl, brotli; with HDRG_WITH_SYSTEM_DEPS zlib, libpng, giflib and lcms2 are the system's). A shared library exports the HDRG_API functions alone; {{src:tests/install/exports.cmake|test_exports}} checks the list.
  • Tests and the internal tools link ${HDRG_INTERNAL}: the static library itself, or the static hdrgrading_internal of the same objects when the library is shared.
  • The installed package carries the layers and the plugin helper too (hdrgrading::headers, hdrgrading::foundation, hdrgrading::gpu, hdrgrading::plugin_shared, hdrg_plugin): a plugin's project builds apart against it ({{page:plugins}}).
  • Optional parts are CMake options: lcms2 (without it no JPEG XL), AVIF, HEIF, SIMD, FMA, the temporal features (HDRG_WITH_TEMPORAL, off by default: the statistics across frames, the motion-compensated interpolation, the multi-frame upscaling), WebGPU, Metal, Vulkan, FFmpeg, the bindings and the GUI, and the built-in plugins a build leaves out (HDRG_PLUGINS_EXCLUDE; {{dev:build}}).

Memory, threads and the floating-point environment

  • Every allocation of the library, its built-in plugins, its GPU layers, libpng, zlib and lcms2 goes through (libjxl's image buffers too) the context's allocator ({{api:hdrg_allocator_t}}); plugins allocate through the API table's mem_*. Outside {{src:src/bindings}}, source files never call malloc directly; buffers a dependency allocates are returned with free, and jpegli's and giflib's own allocations are the system's.
  • A context is used by one thread at a time; distinct contexts are independent. Its pool runs the row-parallel passes with a fixed split, so the thread count never changes the output.
  • Every public entry point and every pool worker pins the floating-point environment (round to nearest, no flush-to-zero), and the build uses -ffp-contract=off.
  • Pixel loops use the library's own float polynomials ({{src:src/foundation/include/hdrgrading/foundation/fmath.h|fmath.h}}) instead of libm, and random-looking values come from a counter hash ({{src:src/foundation/include/hdrgrading/foundation/hash.h|hash.h}}) keyed by position and frame.
