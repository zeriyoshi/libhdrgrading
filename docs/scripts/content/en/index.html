libhdrgrading grades SDR images and video into HDR that looks natural and brighter on HDR displays, and writes it with standard HDR signaling. It is a C11 library with no global state, deterministic output and a plugin ABI for filters and codecs.

What it does

  • Still images: JPEG, PNG, GIF and, with the opt-in AVIF module, AVIF in; an HDR file out. The default is an SDR-based gain-map JPEG (ISO 21496-1), so viewers without HDR still show the correct SDR picture. Two more forms carry a PQ base: hybrid (PQ plus an SDR-recovering gain map) and bare single-layer PQ. The same three forms can be written as JPEG XL and, in opt-in builds (HDRG_WITH_AVIF / HDRG_WITH_HEIF), as 10-bit AVIF and HEIF. See {{page:still}}.
  • Video: a session takes frames (R'G'B' or planar Y'CbCr) and gives single-layer PQ frames with per-frame HDR10+ and SMPTE ST 2094-50 metadata; in a build with HDRG_WITH_TEMPORAL (off by default) the scene statistics follow the frames of each scene, where the default build draws every frame from its own; a seek reproduces the output byte for byte, except under RECURSIVE ({{dev:verification#determinism|the determinism levels}}). See {{page:video}}.
  • Integrations: an FFmpeg filter and helper library, a GStreamer element, a VapourSynth plugin, a browser module (WebAssembly), command-line tools and a GUI. See {{page:bindings}} and {{page:tools}}.

How the picture is graded

The gain of a pixel has two layers:

  1. A diffuse level for the whole frame: every diffuse surface is lifted by the same factor (up to {{api:hdrg_params_t.diffuse_max|diffuse_max}}, 2× by default), so walls, paper, skin and text keep the ratios they have in SDR. Dark, low-key frames stay at the SDR level.
  2. A boost for lights: only regions that show the evidence of a light — a bright region whose surround falls off evenly in every direction (a glow, a bloom, the soft edge of a specular) — rise further, toward the display's peak.

An average picture level budget (a quarter of the peak by default, BT.2408) bounds the whole frame. Every luminance operation is a ratio applied to R, G and B together, so the hue is preserved by construction, and no pixel becomes darker than in the SDR original. Gamut expansion (Oklab, toward Display P3) and saturation are baked into a 3D LUT; grading controls (contrast, clarity, saturation, highlight desaturation) apply on top.

Principles that shape the code

PrincipleWhat it means in practice
Content intent and display are separateThe plan of a frame depends on the content alone ({{api:hdrg_params_t}}); the render fits it to a display ({{api:hdrg_display_caps_t}}). A still file is rendered for an assumed viewing; nothing guesses the display.
Deterministic outputThe same input, settings, build and SIMD tier give the same bytes before encoding, whatever the thread count ({{dev:verification#determinism|the determinism levels}}). Dithers and noise come from a counter hash, transcendental functions from the library's own math, and the work is split the same way for any thread count.
No full-resolution float planesThe three passes decode the caller's code values on the fly through per-channel tables and keep their results on cell grids; the apply pass streams bands to the encoder.
Colors stay as they cameAn input's color is its primaries plus per-channel transfer (ICC, CICP, EXIF, PNG chunks), never squashed into sRGB; the analysis runs on the source values.
Optional work is a stageNoise reduction, deblocking, debanding, scaling and frame interpolation are filters in stages, built in with the same ABI as external plugins, with CPU and GPU versions; so are the check of the judged lights and a video's statistics across frames.
Optional parts are build optionsThe temporal filtering of the video statistics, the motion-compensated interpolation and the multi-frame upscaling are CMake options (off by default), a build can leave the optional built-in plugins out, and every plugin reports its license.

A first program

#include <hdrgrading/hdrgrading.h>

/* jpeg, jpeg_size: an SDR file in memory */
hdrg_context_t *ctx;
hdrg_params_t params;
hdrg_status_t status;
uint8_t *out;
size_t out_size;

status = hdrg_context_create(NULL, &ctx);          /* one thread per core */
if (status != HDRG_OK) {
    return status;
}

hdrg_params_init(&params, HDRG_PRESET_PHOTO);      /* or ANIME, GAME */
status = hdrg_convert(ctx, jpeg, jpeg_size, &params, NULL, NULL, &out, &out_size);
if (status == HDRG_OK) {
    /* out: a gain-map JPEG (the default form and container) */
    hdrg_free(out);
}

hdrg_context_destroy(ctx);

Link with the CMake package (find_package(hdrgrading), target hdrgrading::hdrgrading) or pkg-config (hdrgrading). The functions are documented in the {{dev:api/index}}.
