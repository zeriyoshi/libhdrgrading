The bindings put a session behind the frame model of a media framework. The framework bindings use the public headers alone (the browser module also reads foundation's memory.h), and each one takes the library's settings by the same names (the hdrg-cli option names: {{api:hdrg_setting_at}}, {{api:hdrg_setting_set}}, {{api:hdrg_setting_get}}; a session's through {{api:hdrg_session_setting_set}}; VapourSynth's arguments with _ for -) with numbers as their values. Their own options for the preset, the temporal mode and the latency take the library's value names instead: GStreamer's string properties and VapourSynth's arguments parse them with {{api:hdrg_setting_parse}} (preset=anime, temporal=recursive, latency=low), and FFmpeg's preset, temporal, latency and gpu are AVOption constants.

A statistics window (past / future above 0), RECURSIVE and TWO_PASS need the STATS filter, and an output rate the motion-compensated interpolation hdrg.interp.mc: both come with a build with HDRG_WITH_TEMPORAL, off by default ({{page:video}}). The bindings add no filters of their own, so in other builds these fail with {{api:HDRG_ERR_UNSUPPORTED}}; the examples below that set a window or an output rate assume such a build.

FFmpeg

Two parts: a helper library beside the tool that uses it ({{src:tools/ffmpeg}}), and FFmpeg's own filter ({{src:src/bindings/ffmpeg}}):

  • The helper library {{src:tools/ffmpeg/hdrg_ffmpeg.h|hdrg_ffmpeg.{h,c}}} (libavutil 59 or later, not installed: hdrg-ffmpeg's and the tests'; CMake HDRG_WITH_FFMPEG, on when found): maps an AVFrame's pixel format and color to a session's (planar and NV12 / P010-style Y'CbCr, packed RGB, VideoToolbox frames; PQ and HLG sources are unsupported), wraps frames without a copy (the reference is dropped in release), passes AV1 film grain parameters as {{api:HDRG_SD_FILM_GRAIN}}, and finishes the output frame with its color, the mastering display, HDR10+ and ST 2094-50 side data (read from the library's T.35 bytes with FFmpeg's own parsers).
  • The filter libhdrgrading ({{src:src/bindings/ffmpeg/patches}}: a patch to FFmpeg that adds libavfilter/vf_libhdrgrading.c and --enable-libhdrgrading, in a form fit for upstream). It uses the public API alone, found through pkg-config of an installed shared library. Options: preset, temporal, latency (offline by default), past / future, proxy (the analysis's reduction, under the realtime effort: latency playback or low), w / h, fps, threads, gpu, flash_limit, dither and settings (the library's setting names, numbers as values). Output: yuv420p10, p010 or rgb48 in PQ / BT.2020.
scripts/build_ffmpeg.sh --filter build/deps/hdrgrading
build/deps/ffmpeg-filter/bin/ffmpeg -i in.mp4 \
  -vf "libhdrgrading=preset=anime:settings='diffuse-max=1.5'" -c:v libsvtav1 out.mkv

The tool hdrg-ffmpeg ({{page:tools}}) uses the helper library for whole files.

GStreamer

{{src:src/bindings/gstreamer/gsthdrgrading.c}} is the plugin libgsthdrgrading with the element hdrgrade (GStreamer 1.20 or later; HDRG_BUILD_GSTREAMER). It is a GstBaseTransform whose future window is its latency (reported in the LATENCY query, drained at EOS, reset at FLUSH_STOP). Input: planar YUV of 8 to 16 bits (NV12 / P010 and their kinds too) and packed RGB, the color from the caps' colorimetry and chroma-site; the buffers are mapped and passed without a copy. Output: I420_10LE, bt2100-pq, with the mastering display in the caps. The property latency picks the profile (playback by default) and out-rate sets an output rate. Each measured buffer carries the custom meta HdrgDynamicHdrMeta with the HDR10+ and ST 2094-50 T.35 payloads. The other properties are made from the settings table, with their defaults (unsigned integers, floats and booleans).

GST_PLUGIN_PATH=build/dev gst-launch-1.0 filesrc location=in.mp4 ! decodebin ! videoconvert ! \
  hdrgrade future=4 diffuse-max=1.5 ! x265enc ! h265parse ! matroskamux ! filesink location=out.mkv

VapourSynth

{{src:src/bindings/vapoursynth/hdrg_vapoursynth.c}} adds hdrg.Grade (the module libhdrgrading_vs; HDRG_BUILD_VAPOURSYNTH). Frames may be requested in any order and in parallel and give the same bytes (RECURSIVE only approximately): a request near the session's position advances it, a far one reopens the session the preroll before ({{api:hdrg_session_preroll}}). The color comes from the frame properties (_Matrix, _Transfer, _Primaries, _ColorRange, _ChromaLocation) or the arguments matrix, transfer, primaries, range and chromaloc; preset and temporal (windowed, recursive or static) take names, fpsnum / fpsden set an output rate, and the session is always OFFLINE. Output: 4:2:0 10-bit in PQ / BT.2020, or with format="rgb48" 16-bit R'G'B' in Display P3 (BT.2020 with bt2020=1). Outputs carry the mastering display, the measured light and the T.35 payloads HDR10Plus (FFMS2's form) and HdrgST2094_50.

clip = core.bs.VideoSource("in.mp4")
hdr = core.hdrg.Grade(clip, past=8, future=4, preset="photo", diffuse_max=1.5)

The browser module

{{src:src/wasm/hdrg_wasm.c}} gives JavaScript a function-only interface (hdrg_wasm_context_create, settings by name, hdrg_wasm_convert, the interactive preview's state). It is built five ways (SIMD128 or scalar, single-threaded or pthreads, and SIMD128 with the browser's WebGPU through emdawnwebgpu and JSPI) into hdrgrading-<simd128|scalar>-<st|mt|webgpu>.mjs + .wasm. It converts stills (the same forms as {{api:hdrg_convert}}: a gain-map JPEG by default). The demo in {{src:src/wasm/demo}} converts in a worker and previews on an HDR canvas: {{src:src/wasm/demo/preview.js|preview.js}} runs the library's apply WGSL on the state of a one-frame session ({{api:hdrg_session_receive_state}}) and redraws as the sliders move.
