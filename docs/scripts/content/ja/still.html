{{api:hdrg_convert}} は SDR のファイルのバイト列を受け取り、HDR のファイルのバイト列を返します。{{api:hdrg_convert_raw}} は H.273 の原色と伝達特性の付いた復号済みの画素を受け取ります。どちらも pipeline を 1 回通し、3 つの形のどれかをコンテキストの書き手で書きます: コーデックのプラグインで、既定は JPEG、JPEG XL は内蔵、AVIF と HEIF はモジュールです。

{{fig:still}}

手順

  1. 設定: 3 つの構造体 ({{api:hdrg_params_t}}・{{api:hdrg_display_caps_t}}・{{api:hdrg_encode_params_t}}、NULL は既定) を検査して解決します。静止画は effort の AUTO を QUALITY に、grain_policy の AUTO を PRESERVE にします (RESYNTH は動画のフレームが要り、{{api:HDRG_ERR_UNSUPPORTED}})。{{api:HDRG_OUTPUT_AUTO|output_mode の AUTO}} は書き手の既定の形です。
  2. 形式: コンテキストの読み手が、登録した順にファイルの頭を試します (内蔵の JPEG・PNG・GIF、次にアプリのプラグイン。AVIF のモジュールもここ)。どれも受けなければ (読み手を外したビルドの PNG・GIF も) {{api:HDRG_ERR_UNSUPPORTED_FORMAT}}。
  3. デコード (読み手、{{src:src/host/codec_host.c}}): ホストが確保した絵へ 8 か 16bit の詰めた R'G'B'、その色、その EXIF。画素を確保する前に寸法をコンテキストの max_pixels と比べます ({{api:HDRG_ERR_LIMIT}})。
  4. 向き: EXIF の向き 2〜8 を画素に当て、出力へ運ぶ EXIF のタグを 1 にします。
  5. パイプライン ({{page:pipeline}}): ファイルの想定の視聴で開き、1 回通し、行を書き手へ流します。
  6. 書き手 ({{src:src/container.c}}): 行を帯ごとに、次に形に要るゲインマップとそのメタデータ・プロファイル・光を渡し、書き手のバイト列が出力です。

{{api:HDRG_OUTPUT_GAINMAP}} (JPEG・AVIF・HEIF の既定)本物の SDR の描画 (sRGB、色域を広げたときは Display P3)HDR へのモノクロのゲインマップ (ISO 21496-1)。宣言するヘッドルームは gainmap_headroom_cap_stops (3 段) までゲインマップを読む環境 (iOS 18+ / macOS 15+、Android 15+、Chrome) は HDR、ほかはどこでも正しい SDR

JPEG では、ゲインマップは MPF でつないだ 2 つ目の JPEG のストリームで、ISO 21496-1 のメタデータ、Apple の HDRGainMap XMP、Adobe / Google の hdrgm XMP を付けます (どれも切り替え可)。HAGC のタグは適用で測った SDR へ戻すゲインの曲線を運ぶので、ICC プロファイルだけを残す経路でもトーンマップできます ({{src:src/core/dynamic.c}}・{{src:src/plugins/jpeg/jpeg_mux.c}})。

書き手

{{api:hdrg_context_set_writer}} が以後の変換の書き手を ID とオプション (key=value、{{api:hdrg_options_set}}) で選びます (ID が NULL でオプションがあれば既定の hdrg.jpeg のオプションに、どちらも NULL なら既定に戻します)。hdrg-cli は --format (なければ出力の拡張子) と --format-opt、hdrg-gui は設定の形式で選びます ({{page:tools}})。

書き手コーデック信号オプション
hdrg.jpeg (既定)jpegli、4:4:4ICC (と HAGC)、ゲインマップに MPF + XMPquality (98)・gainmap_quality (90)・hagc・icc_lumi・apple_xmp・hdrgm_xmp
hdrg.jxl (内蔵、系統 jxl: lcms2 が要る)JPEG XL、同梱の libjxl。16bit の基本を 1 枚のフレームで基本の色の符号化 (HDR の基本は BT.2100 の PQ、強度の目標は描画のピーク)。ゲインマップは 8bit の灰色のコードストリームで、ISO 21496-1 のメタデータと代替の色とともに jhgm の箱へ。Exif はその箱へquality (90。100 は可逆)・gainmap_quality (90)・effort (7)

モジュールはアプリが読み込みます ({{api:hdrg_context_load_plugin}})。hdrg-cli と hdrg-gui は隣にあるものを読み込みます。どちらのモジュールも既定では組まず、組むのは自己責任です ({{dev:build}})。エンコード後のバイト列は CPU によって変わりえます (jpegli と libjxl は CPU で命令を選ぶ)。エンコード前の画素は変わりません。AVIF のモジュールのバイト列はシステムのエンコーダのものです。libaom の出力は版で、版によっては使うスレッドの数でも変わるため、ライブラリは AVIF のバイト列が実行や機械をまたいで同じことを保証しません。既定では変換のスレッドで符号化します。threads=1 にすると、同じ libaom なら変換のスレッド数によらず同じバイト列になります (テストはこの設定で走ります)。

想定の視聴

ファイルには尋ねる表示がないので、容器が想定を決めます (表示能力と符号化の設定からの hdrg_container_caps): SDR の白 203 cd/m²、ピークは peak_nits か形式の値 (PQ は 1000 cd/m²、ゲインマップは SDR の白 × 2上限、既定 3 段)、Display P3 (JPEG のような ICC の書き手は lcms2 があるときだけで、なければプロファイルの要らない sRGB。CICP の書き手の PQ とハイブリッドの基本は BT.2020 の入れ物)。表示はゲインマップを自分のヘッドルームと宣言の比で縮めるので、ヘッドルームの小さい表示ではどのゲインも縮み、SDR を下回ることはありません。

出力の寸法

{{api:hdrg_encode_params_t.output_width|output_width}} と output_height (片方 0 で縦横比を保つ) で SCALE 段を通します: {{api:hdrg_context_add_filter}} で足したフィルタ、なければ拡大は {{api:hdrg_params_t.upscaler|upscaler}} の内蔵の scaler、ほかは Lanczos。解析とプランは入力の寸法のままです。

結果

出力のバッファはアロケータを持つので、コンテキストを壊した後も {{api:hdrg_free}} で解放できます。{{api:hdrg_get_last_stats}} は直前に成功した変換が測って当てたもの (拡散面の倍率・光の面積・前後の APL・ノイズ・ブロック性・リンギング・動いた SIMD の階層) を返します。
