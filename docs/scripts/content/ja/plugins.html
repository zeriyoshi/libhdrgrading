任意の処理は段で、フィルタとして動きます。ファイルの形式はコーデックが読み書きします。フィルタもコーデックもプラグインのクラスで、プラグインは API 表を通して登録し、ライブラリをリンクしません。内蔵のフィルタとコーデックも同じ ABI のプラグインで、どれも自分の CMake のプロジェクトとしてライブラリにリンクされ、コンテキストを作るときに登録されます。任意のものはビルドから外せます。

ホストの側 (plugin.h)

  • {{api:hdrg_context_register_plugin}} はアプリにリンクした入口を受け取り、{{api:hdrg_context_load_plugin}} は明示したパスからモジュールを読み込みます (探しません)。表に触れさせる前に ABI の版を照合します。
  • 入口はプラグインの ID・名前・版・ベンダー・SPDX のライセンス・著作権・同梱の部品・状態を報告し、ホストはどの文字列も検証し (長さ・UTF-8・文字の集合・SPDX の構文・SemVer)、アプリの方針 ({{api:hdrg_context_set_plugin_policy}}) に掛けてフリーズします。拒否したプラグインも理由とともに一覧に残ります ({{api:hdrg_context_plugin_info}})。
  • {{api:hdrg_context_filter_count}}・{{api:hdrg_context_filter_info}}・{{api:hdrg_context_filter_option}} がフィルタとそのオプションを一覧し、{{api:hdrg_options_create}} / {{api:hdrg_options_set}} がオプションを key=value の文字列で受け取り、{{api:hdrg_context_add_filter}} が ID でフィルタを以後の変換とセッションの段に足します (PREFILTER は 6 つまで、INTERP・SCALE・ANALYZE・STATS は 1 つずつ)。
  • {{api:hdrg_context_codec_count}}・{{api:hdrg_context_codec_info}}・{{api:hdrg_context_codec_option}} がコーデック (拡張子・役割・書き手の形と既定の形・オプション) を一覧し、{{api:hdrg_context_set_writer}} が以後の静止画の変換の書き手を ID とオプションで選びます (既定は hdrg.jpeg。ID が NULL でオプションがあれば既定の書き手のオプションにし、どちらも NULL なら既定に戻します)。読み手は登録した順に試します。
  • {{api:hdrg_context_set_device}} ({{src:include/hdrgrading/gpu.h|gpu.h}}) はアプリの GPU の device とキューをフィルタと共有します。

プラグインの側 (filter.h)

  • モジュールは {{api:HDRG_PLUGIN_DEFINE}} で書き出す記号を定義し、入口は {{api:hdrg_plugin_api}} を受け取ります。用途ごとに並んだ関数の表です: プラグインの報告・メモリ (コンテキストのアロケータ)・クラス・オプション・インスタンスの申告・交渉・ジョブ・ANALYZE と STATS の段の仕事・読み・書き。
  • 文字列は (ポインタ, バイト数) で渡り、複製されます。境界を enum は渡りません: 定数は uint32_t、ホストのものは中の見えないハンドルで、段が渡すもの (サイドデータ・ANALYZE の段の光の記録・STATS の段のフレーム) はヘッダの素の C の構造体です。コールバックはどれも最後の引数に API 表を受け取るので、プラグインは大域の状態が要りません。
  • クラスは段と性質 ({{api:HDRG_FILTER_PURE}}・{{api:HDRG_FILTER_BANDS}}・{{api:HDRG_FILTER_DETERMINISTIC}}・{{api:HDRG_FILTER_ASYNC}}・{{api:HDRG_FILTER_SEQUENTIAL}}・{{api:HDRG_FILTER_GPU_FRAMES}}: device のジョブが device の上で共有するフレームを受け渡す、{{api:HDRG_FILTER_NO_MOTION}}: 何も動かさない INTERP のフィルタで、間のフレームを動きで頭打ちにしない)、型と範囲の付いたオプション、コールバックを申告します。plugin_set_user と class_set_user は、プラグインのどのフィルタとコーデックも、あるいはクラスのどのインスタンスも読み返すポインタを置きます (filter_plugin_user と filter_class_user、コーデックは {{api:hdrg_plugin_api.read_users|read_users}} と {{api:hdrg_plugin_api.write_users|write_users}})。共有する device・モデル・GPU のクラスのバックエンドなどです。
  • コーデックのクラス ({{src:include/hdrgrading/codec.h|codec.h}}) は読み手か書き手です。読み手はファイルの頭を試し、ホストが確保した絵へ復号して、色 (CICP か ICC)・Exif・向きを報告します。書き手は形 ({{api:HDRG_OUTPUT_GAINMAP}}・HYBRID・PQ) と既定の形、行 (8bit か 16bit の R'G'B')、色の伝え方 (CICP か ICC)、最大の辺を申告します。ホストは行を帯ごとに渡し、終わりにゲインマップと ISO 21496-1 のメタデータ・代替の描画の色・ICC プロファイル・Apple の XMP・測った光・Exif を渡して、書き手のバイト列を受け取ります。
  • ANALYZE のクラス ({{api:hdrg_plugin_api.class_set_analyze|class_set_analyze}}) はその段だけで、create・destroy・analyze ({{api:hdrg_filter_analyze_fn_t}}) を持ち、configure・process・submit はなく、フラグは DETERMINISTIC だけです。判定した光のあるフレームごとに、analyze は lights_get でその記録 ({{api:hdrg_light_record_t}}: 解析したフレームの画素での光の芯の箱・規則の上乗せ・{{api:HDRG_LIGHT_FEATURES}} 個の特徴量) を、lights_frame で解析したフレームを詰めた 16bit の R'G'B' で (セッションの解析の縮小画も。フレームが GPU の上だけにあれば {{api:HDRG_ERR_NOT_FOUND}}) 読み、lights_set_chance で光ごとの確からしさを渡します (渡さなければ 1)。
  • STATS のクラス ({{api:hdrg_plugin_api.class_set_stats|class_set_stats}}) もその段だけで、create・destroy と 6 つのコールバックを持ちます: window (遅延のプロファイルごとに、状態が読むフレームの前の枚数 (シークの preroll が覆う) と、描く前に送られていなければならない後の枚数 (待ち行列が持つ))、fade (送ったときのフレーム {{api:hdrg_stats_sent_t}} からそのフェード {{api:hdrg_stats_fade_t}} へ: そこまでの暗くなる走り・走りの最初のフレームが描いた統計を保つか・解析をやり直す暗くなり方)、frame (その解析、{{api:hdrg_stats_frame_t}})、render (描くフレーム: stats_head が渡す {{api:hdrg_stats_head_t}} のアンカー・key・光の上乗せを書き、stats_queued がその後の待ち行列のフレームを渡す)、fit (計画した APL の係数と、代わりに使うもの)、rendered。filter_stats_session がセッションを表します ({{api:hdrg_stats_session_t}}: モード・プロファイル・ウィンドウ・最初のフレーム・寸法・レート・TWO_PASS の 2 パス目の 1 パス目)。クラスはセッションのバイト列をフレームの純関数に保ちます。
  • インスタンスは変換・セッションで 1 回作り、フレームごとに configure します。create で時間のウィンドウ (filter_set_window)・クリップ (filter_set_clip)・飛行中の枚数 (filter_set_max_inflight、ASYNC は必須)・入力の形式・device を申告し、configure で入力の寸法・色・サイドデータを読んで、出力の寸法と形式か素通しを申告します。
  • ジョブは帯の行 (BANDS) か全画面です。process はその場で終え、ASYNC のフィルタの submit は全画面のジョブを始め、任意のスレッド (ドライバの完了のコールバックも) から job_done で終えます。process のジョブは作業領域を job_scratch から取ります: ホストはワーカーごとに領域を持ち続け、どれも帯のジョブが求めたいちばん大きな大きさまで広げるので、フレームの大きさに届いた後はジョブが何も確保しません。

ABI は {{api:HDRG_PLUGIN_ABI_VERSION}} 1 のままフリーズしていません。フリーズまでどこでも変わりえ、別の版で組んだモジュールは読み込むときに拒否します。プラグインはライブラリと同じヘッダで組みます。

段の実行器

{{src:src/host/stage.c}} がパイプラインのために段のフィルタを動かします:

  • 帯のフィルタは、求めたのりしろ付きの RGB16 の行を受け取ります。全画面のフィルタは、選んだ形式 (RGB16・RGBA16・平面の RGB16 / FP16 / FP32・P016・RGBA8・RGB10A2) のフレームを受け取り、{{src:src/host/format.c}} が RGB16 との間を決定的に変換します。全画面は 16 KiB 境界から 256 バイトの倍数のピッチか、フィルタ自身のメモリ (class_set_frames: IOSurface や CUDA の pinned メモリ) です。
  • 時間のウィンドウとクリップ: セッションは過去 + 未来 + 飛行中のフレームを輪に持ち、ジョブごとにウィンドウ (と、マルチフレームのモデルが 2 つのショットを混ぜないよう、そのショットのフレームの数 job_shot) を渡し、出力を未来の分だけ遅らせます。
  • max_inflight が 2 以上の ASYNC のフィルタは、PLAYBACK と OFFLINE ではその枚数まで飛ばしておき、LOW ではジョブを 1 つずつすぐ待ちます。ある段が land したフレームは、両方のフレームの作り方が同じなら写さずに次の段へ渡します。
  • device の種類を申告したフィルタ (filter_set_device) は、同じ種類の隣り合うフィルタへ出力を device の上で渡します (job_device・job_set_output_device)。
  • BANDS でない SCALE のフィルタは、求めた寸法の代わりに固定の倍率 (2 倍・4 倍) で出してもよく、実行器が自分の Lanczos で合わせます。

プロジェクトとしてのプラグイン

  • {{src:src/plugins}} のディレクトリはどれも自分の CMake のプロジェクトで、hdrg_plugin ({{src:cmake/HdrgPlugin.cmake}}) で作ります: CPU のソース、WebGPU とネイティブの GPU (Metal・Vulkan) のソース、WGSL とその隣の生成した MSL と SPIR-V。{{src:src/plugins/shared}} は複数が共有するもの (ブロックの動き推定、ノイズ低減のノイズの読み方) です。
  • ライブラリのビルドは最初からこれらをリンクします: オブジェクトはライブラリに入り、入口は生成した一覧に入って、どのコンテキストもその順に登録します (フィルタ、次にコーデック)。依存を自分で持つ AVIF と HEIF はいつも読み込むモジュールです。
  • キャッシュ変数 HDRG_PLUGINS_EXCLUDE で任意のものを外せます ({{dev:build}}): bilinear・denoise・deblock・dering・defringe・deband・mctf・interp・fsr・nis・edge・predict とコーデックの jpeg・png・gif・jxl、またはまとまりの filters・codecs・all。polyphase (SCALE 段の Lanczos。固定の倍率を合わせるのも) はいつも残り、コーデックはそれぞれ自分の依存を連れてきます。ライブラリはほかのものなしで動きます: 外した系統のプリセットの既定は切れ (強さは 0、ANIME と GAME の upscaler は Lanczos、PHOTO の動画の粒はノイズ低減がなければ PRESERVE)、明示して使えば {{api:HDRG_ERR_UNSUPPORTED}}、外した読み手だけが読むファイルは {{api:HDRG_ERR_UNSUPPORTED_FORMAT}} です。HDRG_WITH_TEMPORAL_INTERP には interp が、HDRG_WITH_TEMPORAL_SR には edge が要り、hdrg.stats.temporal は HDRG_WITH_TEMPORAL で組まれます。
  • インストールしたパッケージに対して別に組んだプロジェクト (find_package(hdrgrading): hdrgrading::headers・hdrgrading::foundation・hdrgrading::gpu・hdrgrading::plugin_shared) は読み込むモジュール hdrgrading-<名前> になります。{{src:tests/install/run.cmake|test_install}} が {{src:src/plugins/deband}} をそう組みます。hdrg. で始まる ID は内蔵のプラグインのもので、それを名乗るモジュールは拒否されるので、ライブラリから外したプラグインは自分の ID を名乗ります。
  • プラグインは公開ヘッダ・自分のディレクトリ・土台の層 ({{src:src/foundation}}・{{src:src/gpu}}・{{src:src/plugins/shared}}) だけを include し、ライブラリの内部は include しません (scripts/check_style.py が検査)。
