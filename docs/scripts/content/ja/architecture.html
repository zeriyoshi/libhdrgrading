ライブラリは 1 つの静的か共有のライブラリ (libhdrgrading) で、依存が一方向の層からなります。呼び出す側は公開ヘッダを使い、入口が pipeline を動かし、pipeline がその下の処理の本体を使います。

公開 API{{src:include/hdrgrading}}{{src:include/hdrgrading/hdrgrading.h|hdrgrading.h}} (コンテキスト・設定・静止画の変換・統計)、{{src:include/hdrgrading/video.h|video.h}} (セッション・3D LUT の書き出し)、{{src:include/hdrgrading/gpu.h|gpu.h}} (アプリと共有する device・アプリの GPU の上のフレーム・そこで適用を走らせるシェーダと状態)、{{src:include/hdrgrading/metadata.h|metadata.h}} (HDR10+ と ST 2094-50 とその T.35 のペイロード)、{{src:include/hdrgrading/sidedata.h|sidedata.h}} (フレームのノイズ・動き・粒のサイドデータ)、{{src:include/hdrgrading/plugin.h|plugin.h}} (プラグインの登録・フィルタの追加・書き手の選択)、{{src:include/hdrgrading/filter.h|filter.h}} と {{src:include/hdrgrading/codec.h|codec.h}} (プラグインが実装する ABI: フィルタ・読み手・書き手)。公開する関数はどれも HDRG_API を付け、共有のビルドはそれだけを公開します。

パイプライン{{src:src/pipeline}}・{{src:src/pipeline.h}}・{{src:src/host/defaults.c}}系列 (ソースの色とその表・色の LUT・適用の作業領域) とそのフレーム: 解析・プラン・描画・SCALE 段への結び付け・帯ごとの適用。PREFILTER の連鎖を開き、内蔵のフィルタを選びます (GPU のコンテキストでは GPU 版を)。
容器と I/O{{src:src/container.c}}・{{src:src/io}}・{{src:src/host/codec_host.c}}コーデックのホスト (読み手を順に試す、変換の書き手とそのオプション)、ホストが書き手に渡すもの: ゲインマップとそのメタデータ (ISO 21496-1・XMP)、ICC プロファイルと HAGC のタグ、測った光。コーデックそのものはプラグインです ({{src:src/plugins}})。

プラグインのホスト{{src:src/host}}プラグインの登録・検証・方針・フリーズ、モジュールの読み込み、オプション、段の実行器 (帯・全画面・時間のウィンドウ・クリップ・飛行中の ASYNC のジョブ・device のフレーム)、ANALYZE と STATS の段、ジョブのフレームの形式、コンテキストの GPU の device (共有の ABI gpu_share.h でネイティブのハンドルとしてプラグインに渡す)。
内蔵プラグイン{{src:src/plugins}}どれも自分の CMake のプロジェクトで、ライブラリにリンクし、コンテキストを作るときに公開の ABI で登録します: フィルタの系統ごとに 1 つ (scaler・deblock・dering・defringe・deband・空間と時間方向のノイズ低減・フレーム補間。多くは WebGPU・Metal・Vulkan のクラスとそのシェーダも持ち、MetalFX の scaler は Metal だけ)、光の予測器 (ANALYZE)、時間方向の統計 (STATS、任意の HDRG_WITH_TEMPORAL のとき)、コーデック (JPEG・PNG・GIF・JPEG XL)。AVIF と HEIF は同じ形の読み込むモジュールです。任意のものはビルドから外せます (HDRG_PLUGINS_EXCLUDE)。公開ヘッダと下の層だけを include します (scripts/check_style.py が検査)。
GPU の層{{src:src/gpu}}自分のプロジェクト (hdrgrading-gpu): Dawn の上の WebGPU、Metal、Vulkan (実行時に読み込む)、Metal と Vulkan の共通の層 (gk.h)、Apple の CVPixelBuffer、Android の AHardwareBuffer の取り込み、GPU のプラグインの部分 (コンテキストのネイティブの device をプラグイン自身の層のもので包む・ジョブのフレーム)。公開の API ではありません。
foundation{{src:src/foundation}}ライブラリとプラグインの土台の自分のプロジェクト (hdrgrading-foundation): 確保のマクロ、libm を使わない数学 (正確な参照と画素ごとの float の多項式)、カウンタのハッシュ、浮動小数点の環境、スレッド、常駐のプール、単調な時計、ライブラリとプラグインの間で GPU の device と device のフレームを共有する ABI (gpu_share.h)。
WebAssembly の層{{src:src/wasm}}JavaScript 向けの関数だけのインタフェース: 名前での設定・変換・対話プレビューの状態。

ビルドの形

  • ソースは 1 回だけオブジェクトライブラリにコンパイルし、hdrgrading (静的、BUILD_SHARED_LIBS なら共有) はそのオブジェクトと、内蔵プラグイン・foundation・GPU の層・同梱の依存 (jpegli・Highway・libpng・zlib・giflib・lcms2・libjxl・brotli。HDRG_WITH_SYSTEM_DEPS なら zlib・libpng・giflib・lcms2 はシステムのもの) のオブジェクトからなります。共有ライブラリは HDRG_API の関数だけを公開し、{{src:tests/install/exports.cmake|test_exports}} がその一覧を確かめます。
  • テストと内部のツールは ${HDRG_INTERNAL} をリンクします: 静的なライブラリそのもの、共有のときは同じオブジェクトの静的な hdrgrading_internal。
  • インストールしたパッケージは層とプラグインの関数も持ちます (hdrgrading::headers・hdrgrading::foundation・hdrgrading::gpu・hdrgrading::plugin_shared・hdrg_plugin): プラグインのプロジェクトはそれに対して別に組めます ({{page:plugins}})。
  • 任意の部分は CMake のオプションです: lcms2 (なければ JPEG XL もなし)・AVIF・HEIF・SIMD・FMA・時間方向の機能 (HDRG_WITH_TEMPORAL、既定は OFF: フレームをまたぐ統計・動き補償の補間・多フレームの拡大)・WebGPU・Metal・Vulkan・FFmpeg・バインディング・GUI と、ビルドから外す内蔵プラグイン (HDRG_PLUGINS_EXCLUDE。{{dev:build}})。

メモリ・スレッド・浮動小数点の環境

  • ライブラリ・内蔵プラグイン・GPU の層・libpng・zlib・lcms2 の確保 (libjxl の画像の領域も) は、すべてコンテキストのアロケータ ({{api:hdrg_allocator_t}}) を通ります。プラグインは API 表の mem_* で確保します。{{src:src/bindings}} のほかでは malloc を直接呼びません。依存が確保したバッファは free で返し、jpegli と giflib の中の確保はシステムのものです。
  • コンテキストは 1 度に 1 つのスレッドから使い、別のコンテキストは独立です。そのプールは行並列の走査を決まった分け方で動かすので、スレッド数で出力は変わりません。
  • 公開の入口とプールのワーカーはどれも浮動小数点の環境を固定し (最近接丸め、flush-to-zero なし)、ビルドは -ffp-contract=off です。
  • 画素のループは libm の代わりにライブラリ自身の float の多項式 ({{src:src/foundation/include/hdrgrading/foundation/fmath.h|fmath.h}}) を使い、乱数のような値は位置とフレームを鍵にしたカウンタのハッシュ ({{src:src/foundation/include/hdrgrading/foundation/hash.h|hash.h}}) から取ります。
