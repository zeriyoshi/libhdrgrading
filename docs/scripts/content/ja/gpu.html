GPU はどこでも任意です。MetalFX のほかの内蔵の GPU のフィルタにはどれも CPU 版があり、device のないコンテキストは CPU で動きます。シェーダは WGSL で 1 回だけ書き、フィルタとコアは WebGPU の上、または Metal と Vulkan の共通の層の上で 1 回だけ書きます。

内蔵のフィルタはセッションの {{api:hdrg_session_config_t.device|config.device}} があればその種類を先に、次に Metal → Vulkan → WebGPU の順に選び、device がなければ CPU 版を残します ({{src:src/host/defaults.c}})。{{api:hdrg_context_desc_t.gpu_analysis|gpu_analysis}} はセッションの解析が画素を足し合わせる場所を選びます: {{api:HDRG_GPU_ANALYSIS_EXACT}} は CPU で (GPU は画素を運ぶだけで、統計は CPU とビットまで同じ)、{{api:HDRG_GPU_ANALYSIS_FAST}} は GPU で。

シェーダ

  • リファレンスは WGSL で、消費者の隣に置きます: フィルタは各プラグインの wgsl/ (例: {{src:src/plugins/deband/wgsl}})、コアは {{src:src/core/wgsl}} (apply・convert・gather・io・analyze)。
  • {{src:scripts/gen_shaders.sh}} が Tint の CLI (scripts/build_dawn.sh --tint で作る) を compute の入口ごとに走らせ、WGSL の隣に MSL と SPIR-V (msl/・spirv/: {{src:src/plugins/deband/msl}}・{{src:src/core/spirv}})、コアの apply と convert の HLSL ({{src:src/core/hlsl|core/hlsl/}}) を書きます。生成物はコミットし、CI の format のジョブが --check を走らせます。
  • CMake がどのシェーダも配列として埋め込むので (プラグインのものは hdrg_plugin が: WGSL を hdrg_wgsl_<名前>、入口ごとの MSL と SPIR-V をシェーダ hdrg_gk_<名前>_<入口> に)、実行時にファイルは読みません。

GPU のフィルタ

deblock・dering・defringe・deband・空間の NR・MCTF・Lanczos・独自のエッジ適応の scaler・FSR 1・NIS・動き補償の補間の WebGPU・Metal・Vulkan 版は、系統のプラグインのクラス hdrg.webgpu.<名前>・hdrg.metal.<名前>・hdrg.vulkan.<名前> で ({{page:plugins}})、コンテキストのその種類のネイティブの device を自分の GPU の層で包み (下)、{{api:HDRG_FILTER_GPU_FRAMES}} を申告します。deblock・dering・defringe・Lanczos・MCTF・補間は CPU 版とバイトまで同じ、deband と NR は L2 の許容誤差 ({{dev:verification#determinism|決定性の水準}}) で、エッジの scaler・FSR 1・NIS は 1〜2 コード以内で一致します。MetalFX はそうした約束のない別の scaler です。飛行中が 1 枚までの連鎖で隣り合う GPU のフィルタは、フレームを device に置いたまま渡します。

GPU の上のコア

  • {{src:src/core/gpu_core.c}}: セッションに 1 つの device (コンテキストの Metal、なければ Vulkan、なければ WebGPU)、コアのシェーダを最初に使うときに作るプログラム、番号で持つ 40 個のバッファ (CPU から見えるものと GPU だけのもの、アプリの面、GPU に置くフレーム、解析)。
  • {{src:src/core/gpu_convert.c}}: Y'CbCr の入力を CPU と同じ演算の順で 16bit の R'G'B' へ。L2 で一致 (LINEAR は 2 コード、SEGMENTED は 16 コード以内で、1 コードを超える標本はわずか)。
  • {{src:src/core/gpu_apply.c}}: セッションの走査 C (PQ の R'G'B' 16 / 8bit か 4:2:0、光の集計、粒)。CPU と L2 で一致し、失敗したら CPU に戻ります (SCALE の段があるときは使わない: その帯は CPU のまま)。
  • {{src:src/core/gpu_analyze.c}}・{{src:src/core/gpu_gather.c}}: FAST の解析の積算と、GPU に置いたフレームから読み戻す縮小画とノイズのウィンドウ。

HDRG_GPU_AUTO で Y'CbCr の入力、PREFILTER の連鎖がライブラリの GPU のフィルタだけ、SCALE も出力のレートもないとき、フレームを取り込みから適用まで GPU に置きます (遅延のレポートの frames_on_gpu)。既定では WebGPU は置き、Metal と Vulkan は LOW のときだけ置きます (アプリのフレーム config.device ならどのプロファイルでも)。

device とアプリのフレーム

  • {{api:hdrg_context_set_device}} がアプリの device とキューをコンテキストに渡します ({{api:HDRG_DEVICE_METAL}}、{{api:hdrg_vulkan_device_t}} を付けた {{api:HDRG_DEVICE_VULKAN}}、{{api:HDRG_DEVICE_WEBGPU}})。なければライブラリが最初に使うときに自分で作ります。どちらでも、ライブラリとコンテキストのどのプラグインもその device を共有します: プラグインの GPU のクラスは filter_gpu_share でそれを受け取り、ネイティブの device とキューと、それらを一緒に使うのに要るもの (Vulkan のキューのロック、WebGPU の device のスレッド) が渡ります。device の上のフレームはネイティブのバッファのままフィルタの間を渡ります (hdrg_gpu_share_frame_t、{{src:src/foundation/include/hdrgrading/foundation/gpu_share.h|gpu_share.h}})。共有には版があり (HDRG_GPU_SHARE_VERSION)、別の版で組んだモジュールは {{api:HDRG_ERR_UNSUPPORTED}} を受け取り、その GPU のクラスは動きません。自分の GPU の API を使うプラグインは filter_device で素の device とキューを受け取ります。
  • {{api:hdrg_session_config_t.device|config.device}} を付けたセッション (HDRG_GPU_AUTO と Y'CbCr の入力で、フレームを GPU に置けるとき。ほかは {{api:HDRG_ERR_UNSUPPORTED}}) は GPU の上のフレーム ({{api:hdrg_device_frame_t}}) を受け取り、返します: {{api:HDRG_FRAME_BUFFERS}} (コンテキストの device の MTLBuffer・VkBuffer・WGPUBuffer)、{{api:HDRG_FRAME_CVPIXELBUFFER}} (VideoToolbox のデコーダの出力やエンコーダのプール。WebGPU では入力だけ)、{{api:HDRG_FRAME_DMABUF}} (Vulkan、線形の dma-buf)、{{api:HDRG_FRAME_AHARDWAREBUFFER}} (Android の Vulkan: Vulkan の形式で辺が偶数の NV12 か P010 の AHardwareBuffer。フレームごとに 1 回だけ画像として取り込み、面の写しを 1 つのパスにまとめ、Vulkan の外の生産者から 1 回受け取って返します)。
  • またはアプリが自分で適用を走らせます: {{api:hdrg_shader}} と {{api:hdrg_session_receive_state}} ({{page:video}}の「アプリ自身の GPU」)。
