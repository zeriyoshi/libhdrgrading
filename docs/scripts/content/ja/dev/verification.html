テストは Unity ({{src:third_party/unity}}) で書き、CTest で走らせます。どの構成でもテストの一式を全部走らせます: 保証がモジュールをまたぐので、変えた所でテストを選びません。

テストの一式

ディレクトリ確かめること
{{src:tests/unit}}モジュール単体: ノイズの推定、色、プランと光、描画、Y'CbCr の変換、セッションの約束、輝度の規則の評価の基準、SIMD のカーネルと scalar の比較 (checkasm 型)、数学・ハッシュ・スレッド・プール。Metal と Vulkan の下位層。
{{src:tests/conformance}}外から見たライブラリ: 出力の形、ゲインマップ、HAGC、色域、決定性 (スレッド数・FTZ・SIMD の階層)、確保のつり合いと失敗の掃引、プラグインと段の実行器、MCTF、補間、粒、拡大、動的メタデータ、AVIF、HEIF、GPU 版と CPU の比較 (WebGPU・Metal・Vulkan)、fuzz のシード。
{{src:tests/plugins}}テスト用のプラグインのモジュール (scaler、新しすぎる・古すぎる ABI)。
{{src:tests/ffmpeg}}・{{src:tests/gstreamer}}・{{src:tests/vapoursynth}}バインディング: どのフレームもセッションの出力とバイトまで同じ。色・メタデータ・タイムスタンプ・遅延・出力のレート。
{{src:tests/wasm}}node の上のブラウザのモジュール (同じビルドの hdrg-cli とバイトまで同じ)。
{{src:tests/install}}共有ライブラリの公開する記号が HDRG_API の一覧と同じ。install した物を CMake のパッケージと pkg-config で使うプログラムが組める。
{{src:tests/tools}}hdrg-video の HDR10+ と ST 2094-50 の JSON。
{{src:tests/fuzz}}fuzz_convert (hdrg_convert の libFuzzer) と fuzz_seeds (シードのコーパス。test_seeds も使う)。

3 つの段階

段階いつ何を走らせるか

3節目 (フェーズの終わり・push の前)全構成: Linux 17・macOS 9・x86 2・WASM 5 の構成と、FFmpeg のバインディング (macOS)・FFmpeg のフィルタ (macOS と Linux)・hdrg-gui (macOS と、Linux の GStreamer 版と FFmpeg 版) (Valgrind・coverage・fuzz を含む)。ここで見つかった問題は修正のコミットを足して直す

minimal は任意の内蔵プラグインのないビルドでテストの一式を走らせます。外したもののテストは ignore にするか ({{src:tests/test_util.h}} の HDRG_TEST_REQUIRE_BUILTIN・HDRG_TEST_BUILTIN_STATUS)、組みません ({{src:CMakeLists.txt}} の hdrg_builtins_have)。テストの前に空きメモリを見ます: {{src:scripts/jobs.sh}} が並列の数を決め、空きメモリに 1 ジョブ分の余裕もなければ警告して 1 ジョブずつ走らせます。Valgrind は CI のナイトリー ({{src:.github/workflows/nightly.yml}}) だけで、-O0 のままです。

CI

  • {{src:.github/workflows/ci.yml}}: 規約と書式の検査 (シェーダ・Actions の Lockfile・ドキュメントの検査も)、Linux (amd64 / arm64、GCC / Clang、Debug / Release、lcms2 なし、時間方向の機能あり)、サニタイザ、fuzz、FFmpeg のフィルタ、WASM、10 のプラットフォームのカバレッジとその合算、macOS、Windows、GUI。
  • {{src:.github/workflows/nightly.yml}}: Valgrind。
  • {{src:.github/workflows/pages.yml}}: GitHub Pages (サイトとしてのこのドキュメント・デモ・合算のカバレッジ)。

実行ごとに変わらないものは Actions のキャッシュに置き、プルリクエストの外でだけ書きます: 開発イメージのレイヤ、FFmpeg のタグの clone とそのコンパイルの ccache (フィルタのジョブ)、WASM のビルドごと (とデモ) の Emscripten のキャッシュ、実行をまたいで育つ fuzz のコーパス (クラッシュの入力は artifact として上げます)。

決定性の水準

水準対象約束
L0 (公開の保証)CPU の経路のエンコード前の画素・ゲインマップ・メタデータ同じ入力・設定・ビルド・SIMD の階層なら、スレッド数・実行・FP の環境によらずバイト一致
L0xSIMD の階層・コンパイラ・OS の間scalar の参照との許容誤差 (実測: 最大 1 コード、ずれる標本はごくわずか)
L2GPU 版と CPU の間許容誤差。基準はいつも CPU の scalar の参照
約束しないエンコード後のバイト列 (jpegli と libjxl は命令を選び、システムの libaom は版で、版によってはスレッド数でも違う)、機器に固有のフィルタ (MetalFX)—
動画セッションの出力L0 の下で、WINDOWED・TWO_PASS・STATIC は入力の列と設定の純関数: シークしても同じ。RECURSIVE は違う

{{src:tests/conformance/test_determinism.c}} がスレッド数と FTZ、exact な SIMD の階層が scalar と同じことを確かめ、{{src:tests/unit/test_kernels.c}} がどの階層のカーネルも scalar のものと比べます。
