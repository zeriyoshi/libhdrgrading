{{src:docs}} の下は、{{src:docs/scripts}} と {{src:docs/assets}} を除いてすべて生成物で、同じものが GitHub Pages のサイトになります。生成は標準ライブラリだけを使う Python のスクリプト 1 つです (Python 3.9 以降)。

python3 -I docs/scripts/build.py            # docs/ を書き直す (変わるファイルだけ)
python3 -I docs/scripts/build.py --check    # docs/ が古ければ 1 で終わる
python3 -I docs/scripts/build.py --strict   # 図の配置の警告でも失敗する
python3 -I docs/scripts/build.py --out DIR --site --source-base https://github.com/OWNER/REPO/blob/SHA
                                              # 公開するサイト: 資産も含むドキュメントを DIR に、
                                              # トップから demo/ と coverage/ へ、ソースへの
                                              # リンクは GitHub のリポジトリへ

置き換えの記法

ページの元は HTML で、生成のときに置き換えて確かめる記法を含みます。ファイルや記号の名前が変わると、リンクが切れたまま残らずに生成が失敗します:

記法置き換え先確かめること
{​{fig:名前}}図をページに埋め込み (テーマの切り替えが効く)、SVG のファイルへのリンクを付ける図があること。使われない図は警告
{​{src:パス}}・{​{src:パス|文字}}リポジトリのファイルかディレクトリへのリンクパスがあること
{​{api:記号}}・{​{api:構造体.メンバ|文字}}API リファレンスへのリンク公開ヘッダにあること
{​{page:名前}}・{​{man:名前}}・{​{dev:名前}}同じ部・マニュアル・dev/ のページへのリンクページがあること

図

図は Diagram(名前, 幅, 高さ, 題, 説明) に、box (種類で色が決まる: app・api・entry・core・io・plugin・filter・gpu・common・ext・data)、group、edge (辺・アンカーの位置 sa / da・経由点 via・dashed・ラベル)、line、text を足したものです。生成は言語ごとに docs/<言語>/img/<名前>.svg を書き、同じ SVG をページに埋め込みます。文字の幅を見積もって、ラベルが箱からはみ出すときや箱が重なるときに警告します。見積もりは控えめなので、ブラウザでも見て確かめます。SVG はシステムのライト・ダークのテーマに従い、ページに埋め込んだものはページのテーマの切り替えにも従います。

API リファレンス

ヘッダは、宣言の前とメンバの後ろに書いた通常のコメントで自分を説明しています。Doxygen と libclang はドキュメント用のコメント (/** */・///<) しか拾わないので、使うにはヘッダのコメントをすべて書き換えるか、ビルドに依存を足すことになります。そこで {{src:docs/scripts/apiref.py}} がヘッダ自体の並び (clang-format と check_style.py が保つもの) を読みます。分からない行に出会えばエラーで止まり、ヘッダの HDRG_API の関数がすべてリファレンスに載っていなければ生成が失敗します。英語のページはコメントを書いたまま載せ、日本語のページは日本語の訳を載せてその下に英語の原文を開けます。どちらの識別子も項目へリンクします。

訳は {{src:docs/scripts/api_ja}} にヘッダごとに置き、コメントの英語のハッシュを鍵にします。英語の変わらないコメントは訳をそのまま使い、新しいコメントと変わったコメントだけを訳します (手順・決まり・語は {{src:docs/scripts/api_ja/README.md}})。普通に生成するとファイルをヘッダに合わせ (新しいコメントと変わったコメントは "ja": null で入り、使わなくなったものは消える)、訳のないコメントや原文と形の合わない訳 (まとまり・箇条・識別子) があれば失敗します。1 つのファイルは python3 -I docs/scripts/apiref.py docs/scripts/api_ja/<ヘッダ>.json で確かめます。

確かめる

公開ヘッダかページの元を変えたら --check を走らせ、生成物を作り直してコミットする必要があるかを見ます。CI のリポジトリの検査が --check --strict を走らせるので ({{src:.github/workflows/ci.yml}})、マニュアルを作り直さずにヘッダを変えるとそこで失敗します。

公開

GitHub Pages ({{src:.github/workflows/pages.yml}}) はドキュメントをサイト全体として --out site --site と、GitHub のそのコミットを指す --source-base で作り直すので、ソースへのリンクはページが説明するファイルへ届きます (ディレクトリは tree/、ファイルは blob/、API リファレンスの行のアンカーも)。サイトのトップ (ドキュメント自身の index.html) は、ほかのジョブが隣に置く WASM のデモとカバレッジへもリンクします (CI の実行に合算のカバレッジがなくても、その場所に案内のページを置いてサイトを公開します)。{{src:scripts/wasm_demo.sh}} はデモ付きの同じサイトを build/web に組むので、手元で試せます。CMake のターゲット hdrg_web (cmake --build <ビルド> --target hdrg_web) は、デモなしのサイトを <ビルド>/web に組みます。コミットするドキュメントは、手元の checkout で読めるよう相対のリンクのままです。
