C のコード

  • C11。stdint.h の固定幅の型と bool、収まる最小の型、符号が要らなければ符号なし。
  • 変数の宣言は関数の最上位だけで、入れ子のブロックや for の見出しでは宣言しません。1 つの型は 1 つの宣言文 (同じ型のポインタ・配列・初期化付きも同じ文) で、順は const のもの、プロジェクトと依存の型、uint64_t … uint8_t、int64_t … int8_t、size_t、bool、char、double、float、void *。
  • {} は省きません。typedef はどれも _t で終わります。
  • ファイルの並び: include、マクロ、static inline 関数、static 関数、通常の関数、公開する関数 (extern を付ける)。
  • 処理のまとまりごとに空行 (宣言の後、ブロックの前 (直前の文が見出しで確かめるものを代入しているときを除く)、閉じ括弧の後、ほかの文に続く return の前、確保・代入・副作用・後始末の間)。
  • コメントはコードから読めないことだけ。どのファイルにも SPDX のヘッダ (Apache-2.0 OR MIT)。
  • 書式は .clang-format、静的解析は .clang-tidy (LLVM 23、zendriver の common/ と同じ)。

メモリ

  • src/ の中では malloc などを直接呼びません: 本体は hdrg_mem_* (コンテキストのアロケータ、そろえた確保は hdrg_mem_aligned_alloc)、内蔵フィルタと GPU の層は API 表の mem_*。依存が確保して解放を求めるものだけを free で返し、その行に "the dependency's" と書きます (check_style の raw-alloc)。
  • リアルタイムの経路では全解像度の float の面を持ちません。

決定性

  • 乱数とディザは {{src:src/foundation/include/hdrgrading/foundation/hash.h|hash.h}} のカウンタのハッシュ (鍵・x・y・標本) だけ。rand() と逐次の乱数の列は使いません。
  • 超越関数は {{src:src/foundation/include/hdrgrading/foundation/math.h|math.h}} (画素のループでは {{src:src/foundation/include/hdrgrading/foundation/fmath.h|fmath.h}}) を使い、libm の powf・expf・log2f は使いません。
  • 並列はコンテキストのプールを決まった分け方で使い (hdrg_exec_t)、出力がスレッド数で変わることはありません。FP の環境は入口とワーカーで固定し、縮約はしません (-ffp-contract=off)。
  • 時間方向の 3 つの機能はプラグインで、ライブラリは段の ABI だけで呼び、ほかの内蔵プラグインと同じく選んで組みます (HDRG_WITH_TEMPORAL): フレームをまたぐ統計は STATS のプラグイン ({{src:src/plugins/stats}})、動き補償の補間は interp の中 (HDRG_INTERP_MC)、多フレームの拡大は edge の中 (HDRG_SCALE_TEMPORAL)。本体はビルドを知りません: セッションの既定はあるフィルタに従います (STATS のフィルタがあれば過去のウィンドウ)。それに触れる処理はそのプラグインに置き、テストは生成する HDRG_BUILTIN_STATS / _INTERP_MC / _SCALE_TEMPORAL で分け、OFF (既定) と ON (temporal) の両方で組めてテストが通ることを保ちます。

公開 API とプラグインの ABI

  • 公開する関数は公開ヘッダに HDRG_API を付けて 1 行で宣言します: CMake がその行から共有ライブラリの公開の一覧を作り、test_exports が確かめます。
  • 状態の値・種類・フラグは enum でなく決まった uint32_t / uint8_t の定数。育つ構造体は struct_size を持ちます。
  • フィルタの ABI ({{src:include/hdrgrading/filter.h}}) はフリーズまで版 1 のままで、それまでは表の並び・シグネチャ・意味を版を上げずに変えてよく、表は用途ごとに並べます。
  • 内蔵プラグイン ({{src:src/plugins}}) は公開ヘッダ・自分のディレクトリ・土台の層 ({{src:src/foundation}}・{{src:src/gpu}}・{{src:src/plugins/shared}}) だけを include し、コアは include しません (check_style の filter-include)。外部のプラグインとバインディングは公開ヘッダだけです。プラグインからの文字列は長さを明示して受け取り、検証して複製します。
  • HDRG_PLUGINS_EXCLUDE で外せる内蔵プラグイン ({{src:src/plugins/CMakeLists.txt}} の一覧) はそのまま保ちます: ライブラリはどれがなくても動き (既定は切れ、明示して使えば {{api:HDRG_ERR_UNSUPPORTED}})、minimal がそれを保ち、テストは外したものを避けます。

SIMD とシェーダ

  • カーネルは ISA ごとの基本演算 (v_<isa>.h) の上に {{src:src/kernels/vmath.h}} で 1 回だけ書きます。どの階層も scalar の参照の演算の順をなぞり、近似の命令は使いません。積の直後の和は hdrg_vf_fma と書き、融合するかは HDRG_WITH_SIMD_FMA で決まります。カーネルを足すときは test_kernels の比較も足します。
  • シェーダのリファレンスは WGSL で、MSL / SPIR-V / HLSL は {{src:scripts/gen_shaders.sh}} で作り直してコミットします。ループの中の var には必ず初期化子を書きます (lavapipe は初期化子なしの var を回るたびに 0 にしない)。
  • GPU の結果は CPU と L2 で一致させ、GPU のテストに比較を足します。

プリセットと評価

  • PHOTO の既定値は忠実さの数値 (16bit の真値・劣化のない元との PSNR・色差の誤差・質感が残るか) で詰めます。
  • ANIME の既定値と手法の採否は、200〜400% の拡大での目視で決めます。数値は回帰の確認に使い、順位付けには使いません。線そのものには既定で手を出しません。
  • 評価の画像はリポジトリにも公開のページにも入れません。
